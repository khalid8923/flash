Project Name: FLASH (Cognitive Training Platform)

Project Purpose: A browser-based cognitive training platform that serves as a free, science-backed alternative to Lumosity / Peak / BrainHQ.

Core Problem Being Solved:

Existing brain-training platforms are paid and overclaim scientifically

Content is static (users memorize answers over time)

One-size-fits-all experience

No deep performance analysis

Minimal or no Arabic support

Target Users:

Adults 25-45 seeking measurable cognitive progress

Students wanting a sense of advancement

Skeptical users who distrust "brain games" claims (need a serious, non-childish tool)

Target Platform: Web browser (offline-capable via file:// + PWA)

Business/Product Concept: Free + open source (MIT license)

Main Value Proposition:

AI-generated infinite content (no two sessions identical)

AI adaptive difficulty (real-time personalization)

AI Coach (conversational, knows user data)

Full EN + AR support with RTL from day one

$0 monthly cost (all infrastructure on free tiers)

Main Differentiators vs. Competitors:

Feature	Lumosity	Peak	BrainHQ	FLASH
Price	$11.99/mo	$9.99/mo	$14/mo	Free
Scientific papers	✗	✗	✓	✓

Core User Experience: User opens dashboard → sees cognitive profile → plays a session → sees analysis → gets next recommendation → returns daily. Tone: Instrument, not game. Serious, editorial, scientific.

Long-Term Vision: Investor-ready demo → 50-100 early users → seed funding → 50K users with live AI Coach.

Change 1: 41 games → 36 games (originally) → 42 games (current)

Change 2: Monolithic dashboard → Modular dashboard v2

Before: frontend/dashboard/FLASH.html (monolithic, ~29 KB, 900+ lines)

Why: Extending monolith required editing single 900-line file

Old file preserved as _legacy/FLASH.html

Change 3: localStorage-only → Backend + localStorage hybrid

Before: Each game stored PB/history/daily/badges in localStorage

Change: Backend provides /sessions ingestion, PB, badges; localStorage becomes queue/offline buffer

Why: Multi-device sync, real cognitive profile, AI analysis

Change 4: Single AI provider (Groq) → Multi-provider router

Before: Groq only

Change: Groq → OpenRouter → Gemini → Rule fallback with circuit breaker

Why: Reliability, cost fallback

Change 5: Demo user only → Player Auth (OTP)

Before: getOrCreateDemoUser() on every request

Change: Email OTP + session tokens + optionalPlayer middleware

Why: Real users for investor demo

Change 6: Design v1 (Cyan/Pink) → Cortex Reef → Rose/Neon (current)

v1 (v6.0 docs): Cyan #00EEFF + Pink #FF0077 on dark #04040A

Cortex Reef (experimental, 2026-10-09): Vellum #EFE7D3 + Ink #1E2230 + Rubric red #B2341A

Rose/Neon (current): Light Rose #FFF1F2 + #EC4899 accent; Dark Neon #000000 + #39FF14

Why: v2 modular dashboard selected Rose/Neon as canonical

Change 7: Monolithic error handling → Comprehensive Error System

Before: Try/catch scattered, no unified classification

Change: Full error system — AppError class, PostgreSQL mapping, central error handler, safe-fetch wrapper, offline-first save queue, timer integrity, achievement guard, network monitor, error UI, accessibility, multi-tab sync

Why: Prevent data loss, no leaked secrets, graceful degradation

Game Session Flow
text
1. Shell creates MessageChannel
2. Load iframe (sandboxed, no allow-same-origin)
3. Wait for 'load' event
4. Send flash:init with port2
5. Game sends flash:ready
6. User plays
7. Session ends → Game sends flash:session (raw trials)
8. Shell validates + queues for sync via save-queue
9. Shell sends flash:ack
10. If online → save-queue flushes to POST /sessions
11. If offline → stored in localStorage, flushed on reconnect
12. Backend derives metrics, PB, badges, engine decision
13. Response → Shell updates UI
14. Session Recap fetched via POST /ai/recap
15. Modal shown with AI-generated analysis

Method: Email OTP (passwordless)

Flow:

POST /auth/otp/request → email → 6-digit OTP sent via Resend
POST /auth/otp/verify → email + code → session token
Session token used as Authorization: Bearer ses_...
Rate limits: 5 OTP requests per hour per email

OTP: 6-digit, constant-time compare, attempts + expiry tracked

Session: idle + absolute expiry

Tables: auth_identities, auth_sessions, auth_otp_codes

Middleware: requirePlayer (strict), optionalPlayer (fallback to demo)

Frontend: auth.html (implemented), auth-guard.js (implemented)

Roles (5): owner, ops, science, support, analyst
